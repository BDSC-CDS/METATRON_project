# METATRON

## METATRON Project Presentation

METATRON aims to develop an LLM-based assistant designed to support hepatobiliary (HPB) surgeons during Multidisciplinary Tumor Board discussions by helping them provide treatment recommendations for specific clinical cases.

## Repo: `rag_db` – Retrieval-Augmented Generation (RAG) Document Store

This repository illustrates the **step-by-step construction of the Milvus vector database** used as the document store for the METATRON RAG pipeline.

> **Note:** This repository is primarily intended to document and illustrate the different steps involved in building the RAG database. The complete pipeline is not fully reproducible from the repository alone, since the original PDF studies are not included for storage and distribution reasons. However, the intermediate data produced by the pipeline, including the processed Markdown documents, are provided where applicable.
The subsequent step of the METATRON pipeline, specifically the generation of treatment recommendations for clinical cases, does not require the strict execution of this repository's pipeline, since it is possible to use pre-saved paragraphs already extracted using the corresponding queries for each case, available in `generation/rag_results`.


The pipeline processes a collection of scientific PDF studies concerning topics such as primary tumors and liver metastases and consists of the following steps:

### 1. Extract study information

`01_studies_information.py`

This script processes the original PDF studies and uses an LLM to extract bibliographic information, including:

* first author
* publication year
* title

The original PDF studies are **not included in this repository** due to their size.

The script produces:

```text
../data/studies_information.csv
```

which contains the extracted bibliographic information for the studies.

The PDF studies must be organized inside the internal `studies/` folder according to the following structure:

studies/
├── PrimaryTumor/
├── LiverMetastases/
├── ExtraHepaticMetastases/
└── RectalPrimaryTumor/

### 2. Process PDF documents

`02_process_pdf.py`

This script converts the PDF studies (organized as detailed above) into Markdown documents and splits the extracted content into meaningful paragraphs/chucks.

The resulting Markdown files are provided in the repository and can therefore be used to inspect the intermediate output of this step.

The script also produces the paragraph-level dataset:

```text
../data/paragraphs_tb.csv
```

which contains the paragraphs that will subsequently be embedded and stored in Milvus.

### 3. Build the Milvus vector database

`03_build_vector_db.py`

This script:

1. Loads the paragraphs generated in the previous step.
2. Generates an embedding for each paragraph using the configured embedding model.
3. Creates a **Milvus database instance**.
4. Creates the required collection and schema.
5. Stores the paragraph embeddings together with the relevant auxiliary information.

The LLM and embedding models, as well as the Milvus configuration, are specified in the `models.py` configuration file.

### 4. Create and test semantic search

`04_create_and_try_filter.py`

This script enables semantic retrieval from the Milvus database and demonstrates how to perform similarity searches with optional attribute-based filters.

The filters can be used to restrict the retrieved documents according to the available metadata.

## Configuration

The models and database configuration are defined in:

```text
models.py
```

The configuration specifies:

* the LLM used by the pipeline;
* the embedding model used to generate paragraph embeddings;
* the URL of the LLM and embedding model servers;
* the Milvus database URI.

By default, the project is configured to use a local Ollama instance for both the LLM and embedding model. These settings can be modified in `models.py` according to the local setup.

## Creating the Milvus database locally

To reproduce the construction of the local Milvus database, the scripts should be executed **sequentially, one at a time**, since each step uses the output generated by the previous one.

The recommended order is:

```text
01_studies_information.py
        ↓
studies_information.csv
        ↓
02_process_pdf.py
        ↓
Markdown files + paragraphs_tb.csv
        ↓
03_build_vector_db.py
        ↓
Local Milvus database
        ↓
04_create_and_try_filter.py
```

### Step 1 – Extract study information

Run:

```bash
uv run python 01_studies_information.py
```

This step requires the original PDF studies, which are not included in the repository.

It produces:

```text
../data/studies_information.csv
```

### Step 2 – Process the studies

Run:

```bash
uv run python 02_process_pdf.py
```

This step uses the PDF studies and produces the Markdown documents and:

```text
../data/paragraphs_tb.csv
```

The Markdown files generated by this step are provided in the repository.

### Step 3 – Build the Milvus database

Run:

```bash
uv run python 03_build_vector_db.py
```

This script creates the local Milvus instance, generates the embeddings and populates the vector database with the processed paragraphs.

### Step 4 – Test semantic retrieval

Once the database has been created, run:

```bash
uv run python 04_create_and_try_filter.py
```

This script can be used to test semantic search and metadata-based filtering on the locally created Milvus database.
